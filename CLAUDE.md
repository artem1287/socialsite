# Statline — project guide for Claude Code

A **"TikTok for statistics"**: a single-page web app that shows a scrolling, personalized
feed of ~100 statistics sourced (conceptually) from 50 public statistical APIs. Built as
one self-contained HTML file. No build step, no framework, no server.

## Files
- `index.html` — the app (this is what GitHub Pages serves). **Source of truth.**
- `statline.html` — an identical copy (the original filename). Keep the two in sync, or
  collapse to one if you prefer; `index.html` is the one that matters for hosting.
- `README.md` — short public description.

There is **no toolchain**. To run it: open `index.html` in a browser, or enable GitHub
Pages (Settings → Pages → branch `main` / root) → served at
`https://artem1287.github.io/socialsite/`.

## How to edit
Everything lives in `index.html`: one `<style>` block, the markup, and one `<script>`.
Edit that file directly. When changing the app, make the same edit in both `index.html`
and `statline.html` (or delete `statline.html`). It was originally authored as a Claude
Artifact, but the repo copy is now the canonical version — just edit the file.

## Important constraint: data is embedded, not fetched
The 50 listed APIs mostly need keys and/or block cross-origin browser requests (CORS), and
a hosted static page can't call them live anyway. So **all statistics are embedded as
plausible latest-2026 values**, each attributed to its real source. Market/live figures
(Bitcoin, S&P 500, oil, rates) are approximate, not real-time. If you ever wire in live
data, you'll need a backend/proxy or serverless functions — the browser alone can't do it.

## Code map (inside `index.html`, in the `<script>`)
- `CATS` — topic definitions (economy, climate, health, sports, science, work, civics) with colors.
- `DATA` — the ~100 statistics. Two kinds of entries:
  - **Time series (default / `type:"line"`):** fields `cat, label, src, verified, updated,
    up, debate, ago, v` (2026 headline), `u` (unit), `y0` (first year), `s0` (that year's
    value), optional `wob` (jitter amplitude). A monthly series from Jan `y0` → Oct 2026 is
    generated by `trend()`, then **rounded to the headline's display precision** so points
    that read the same value ARE the same (no fake wiggle). The headline `v` is the exact
    Oct-2026 endpoint.
  - **Breakdowns (`type:"bars" | "hbars" | "donut"`):** fields `items:[{n,v}], pfx, sfx,
    idec, sub` — these are snapshots/rankings/compositions, NOT trends (no time axis, no
    range control, no "since"). Added for variety so the feed isn't only "line goes up."
- Build step after `DATA` is declared: `DATA.forEach(...)` assigns ids, parses formats,
  builds series; then an IIFE **interleaves** breakdown cards through the feed.
- Charting:
  - `chart(d)` — line chart. Stretched SVG (`preserveAspectRatio="none"`) for the
    line/area/axes; **crisp labels, dots and the hover marker are HTML overlays** (so text
    isn't distorted). Straight angular segments, sharp peaks (miter joins, point jitter).
  - `bindCharts()` — adds hover: vertical guide + tooltip showing value, **exact month**,
    and unit at the nearest point. Guarded with `wrap._bound` so re-binding doesn't
    duplicate listeners.
  - `barsHTML / hbarsHTML / donutHTML` — the breakdown chart types (HTML/SVG, `PAL` colors).
- Time model is **month-absolute** (`END_ABS` = Oct 2026, `mLabel`, `timeTicks`,
  `rangeLabel`, `viewOf`). Per-card range picker options come from `winLen`/`effPeriod`.
- `regionFor(d)` — maps each source to a country/region flag + label (US, Euro area,
  France, UK, Germany, Estonia, OECD, Global…). Shown as a chip on every card.

## Recommendation engine (the core feature)
State in `ALGO` (persisted to `localStorage`): `iv` (interest vector per topic), `seen`
(impressions per topic), `ic` (meaningful interaction count).

- **Signal weights** (`applySignal` / `WEIGHT` / `dwellWeight`): dwell `<0.5s −1`, `<1s −2`,
  `1–3s −0.5`, `3–8s +1`, `8–20s +3`, `20s+ +5`; like `+2`, save `+6`, comment `+7`,
  share `+5`, open-detail `+3`, **not-interested `−8`**. Dwell is measured with an
  `IntersectionObserver` (card ≥50% visible); `flushDwell` commits open timers on re-render.
- **Phases** (`phaseInfo`, by `ic`): Calibrating `<5` → 80% explore (+ onboarding chips,
  feed forced 100% diverse), Learning `<30` → 45%, Tuned `30+` → 18%. Shown as the chip
  next to the tabs (`updateStatus`).
- **Ranking** (`rankFeed`): interleaves an exploit list (interest vector + engagement prior)
  with an explore pool. The explore pool is `diversePool()` — **round-robin across topics,
  least-seen first** — which is what prevents the "all sports" clustering during
  calibration. Explore picks get a ✦ Experimental badge (except during calibration).
- **Endless feed**: `appendBatch()` renders a freshly-ranked **set of 3** at a time;
  `setupLoadObserver()` loads the next set as you near the bottom; it loops when exhausted.
  So each new batch reflects the just-updated interest vector.
- **Detail modal**: tapping a card body opens it (counts as the +3 open signal).

## Conventions
- Theme-aware (light/dark via CSS tokens on `:root`). Fonts: Bricolage Grotesque (display),
  Hanken Grotesk (body), Spline Sans Mono (labels) via Google Fonts.
- No all-caps text (deliberate). Full-screen layout, no outer panel border.
- When adding a stat, copy an existing `DATA` entry of the right `type` and fill the fields;
  everything else (series, range picker, region chip, ranking) is derived automatically.
